# biliweb

一个**只依赖 Python 标准库**的第三方 B站网页客户端。搜索、看视频、下载、导出观看历史，就这些。

> **仅供学习和个人研究使用。** 本项目通过非公开接口与 B站 通信，与哔哩哔哩官方无关，
> 未获官方授权，不是官方客户端。请勿用于商业用途、批量抓取或任何可能影响平台正常服务的场景。
> 使用产生的账号风险、数据风险由使用者自行承担。如有侵权请联系删除。

## 它故意不做什么

这是它存在的理由，不是没写完：

- 没有首页推荐流、相关推荐、猜你喜欢
- 没有动态流、自动连播、无限滚动

只有 **搜索 → 看 → 互动**。打开页面是一片空白加一个搜索框，你必须先想清楚要看什么。
信息流产品靠「不用想就知道看什么」拿走时间，这里把这一步还回去。

## 功能

| 功能 | 说明 |
|---|---|
| 搜索 | 视频 / UP主 / 专栏 三类，分页 |
| 视频详情 | 标题、封面、BV号与 av号（可复制）、UP主、播放点赞硬币收藏数、简介、原页链接 |
| 在线预览 | 点一下在页内播放，服务端合并音视频后推流，画质取账号上限 |
| 下载 | 选清晰度（360P–4K，按账号实际能拿到的档位列），文件名带清晰度 |
| 点赞 / 投币 / 收藏 / 关注 | 投币有二次确认；收藏可选收藏夹 |
| 评论查看 | 视频和专栏都支持，20 条一页，显式翻页 |
| UP主主页 | 资料、粉丝数、投稿列表（分页加载）、关注/取关 |
| 专栏阅读 | 正文渲染（服务端已剥离 script 与事件属性，防上游 HTML 注入） |
| 观看历史 | 今天 / 近7天 / 近30天 / 近一年 / 不限，或自定义日期区间 |
| 导出 JSON | 把选定时间段的历史导成 JSON 下载 |
| 操作诊断 | 一键跑一对可逆的赞/取消赞，把原始错误码摊在页面上，便于排查 |

## 环境要求

- **Python 3.9+**（实测 3.13）。不需要 pip install 任何东西。
- **ffmpeg**（可选但建议）：在线预览和 1080P 以上下载需要它来合并音视频。
  没有它也能跑，下载会自动退到 B站 已合好的单文件流（清晰度较低）。

## 快速开始

### 1. 登录，拿到 cookie

```bash
python3 bili_login.py
```

它会打印一个链接。在同一台设备上打开这个链接、点「确认登录」，脚本会自动轮询并把
`cookies.txt` 写在当前目录。不需要扫二维码（同一个设备没法扫自己的屏幕），当然扫码也支持。

登录态只会存在 `cookies.txt` 里，不会发往任何第三方。有效期约一个月，过期重跑即可。

### 2. 启动

```bash
python3 server.py                          # 127.0.0.1:8000
python3 server.py --port 8090              # 换端口
python3 server.py --host 0.0.0.0 --token 你的口令   # 局域网/其它设备访问
python3 server.py --selftest               # 只读自检，不启动服务
```

启动后浏览器打开 `http://127.0.0.1:8000/`。带了 `--token` 就打开 `http://<地址>:<端口>/?t=你的口令`。

### 命令行参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--host` | `127.0.0.1` | 监听地址，IPv6 写具体地址或 `::` |
| `--port` | `8000` | 端口 |
| `--cookies` | 脚本同目录的 `cookies.txt` | cookie 文件路径 |
| `--token` | 空 | 访问口令。**监听非本机地址时建议一定带上** |
| `--ffmpeg` | `ffmpeg` | ffmpeg 路径 |
| `--bundle-cookies` | 关 | `/biliweb.tar.gz` 里是否带上 `cookies.txt`。压缩包等于账号控制权，非必要不开 |
| `--selftest` | — | 只读自检：搜索、评论、专栏、清晰度、收藏夹各打一遍 |

## 使用说明

### 搜索

顶部输入关键词，用「视频 / UP主 / 专栏」切换类型。搜索词和页码会记在浏览器里，
刷新后还在。「下一页」是显式按钮，不会自己往下加载。

### 看视频

点任意一条结果进入详情页。页面自上而下是：封面 → 标题 → 数据 → BV号（可复制）→ UP主（点击进主页）
→ 点赞/投币/收藏/关注 → 在线预览 → 下载 → 简介 → 评论。

- **在线预览**：服务端把音视频合并后边下边推给你。这种流没有文件长度，所以进度条拖不动；
  要拖进度或要原始清晰度就下载。
- **下载**：弹出清晰度列表，每档标注分辨率、编码和估算大小，选一档点「下载」。
  手机上由系统浏览器接管：iOS 进「文件 → 下载」，安卓进通知栏或 Download 目录。
  依赖 ffmpeg 合并；没有 ffmpeg 时会退回单文件流并降低清晰度。
- **点赞 / 投币 / 收藏 / 关注**：按钮状态立即更新。B站 的状态接口有数秒延迟，
  所以这里以写操作成功为准，不回读状态。
- **投币**：不可撤回，有二次确认，可选 1 或 2 枚。已经投过的视频会禁用按钮。
- **操作诊断**：如果点赞之类的写操作报错，点这个按钮。它会跑一对可逆操作
  （没赞过就赞→取消，已赞过就取消→赞，净效果为零），把 cookie 状态、每一步的原始
  code/message、前后状态全部打印在页面上，长按可复制。

### 看 UP 主

在详情页点 UP主 那一行，或在搜索结果里切到「UP主」再点。主页显示资料、粉丝数、投稿总数和投稿列表，
点「加载更多投稿」继续翻页。

### 专栏

搜索类型切到「专栏」，点进去直接读正文。评论同样支持翻页。

### 观看历史

顶部「历史」按钮。先选时间段（今天 / 近7天 / 近30天 / 近一年 / 不限，或直接改日期区间），
再选翻页上限（5 / 15 / 40 / 100 页，每页 30 条），点「查询」。

- 列表只显示**标题 + UP主 + 时间**，不加载封面，所以很快。
- 「导出 JSON」把当前时间段导出成文件。文件结构：

```json
{
  "exported_at": "2026-10-02 01:09:11",
  "source": "biliweb（第三方网页客户端，非 B 站官方导出）",
  "account": {"mid": "<你的 mid>", "uname": "..."},
  "range": {"start": 1788192000, "start_local": "...", "end": 1788278399, "end_local": "..."},
  "count": 90, "pages": 3, "oldest": 1788..., "newest": 1788...,
  "truncated": false,
  "note": "时间段已完整取完",
  "items": [
    {"view_at": 1788..., "view_at_local": "2026-10-02 01:04:27",
     "business": "article", "title": "...", "author": "...", "bvid": "", "oid": 15788794}
  ]
}
```

`truncated: true` 表示翻到页数上限还没取完，把页数调大再导一次。

### 前端路由

详情页状态存在 URL 里，刷新、浏览器前进后退、把链接发给别的设备都能回到原来那一页：

```
#video/BV13Yao6fEwa
#article/15788794
#user/2929582
#history
```

## 部署到手机

本地跑时「服务器」就是手机，所以流量只走一趟，在线预览和下载都不必走外网中转。

**Termux（Android）**

```bash
pkg update && pkg install python curl
# 直接把项目文件放到 ~/biliweb，或在服务器上打包后下载：
#   curl -O "http://<你的服务器地址>:8090/biliweb.tar.gz?t=$TOKEN"   # 需服务器加 --bundle-cookies
#   tar xzf biliweb.tar.gz

cd biliweb
python3 bili_login.py        # 登录，产出 cookies.txt
python3 server.py --port 8090
# 手机浏览器打开 http://127.0.0.1:8090/
```

- 想在后台常驻：`termux-wake-lock` 防系统休眠，然后 `nohup python3 server.py --port 8090 &`。
- 想开机自启：装 Termux:Boot，把启动命令写进 `~/.termux/boot/start-biliweb.sh`。
- 只在本机访问不需要 `--token`。
- 建议 `pkg install ffmpeg`，否则下载清晰度受限。
- Termux 请从 F-Droid 或 GitHub 安装，Play 商店那个版本已废弃。

**iSH（iOS）**

```bash
apk add python3 curl
python3 server.py --port 8090
```

iSH 是 32 位 x86 用户态模拟、无 JIT，慢，但本项目只用标准库不需要编译。iOS 上更推荐
[a-Shell](https://holzschu.github.io/a-Shell_iOS/)，自带 Python 且快得多。

## 安全边界

- `SESSDATA`（登录态）和 `bili_jct`（CSRF token）只存在于服务进程内存和 `cookies.txt`，
  **不下发到前端、不写日志**。前端拿到的只有渲染好的数据。
- 这两个值合起来等于账号控制权：`bili_jct` 能点赞、投币、发评论。不要外发，不要提交到仓库
  （`.gitignore` 已排除）。
- `--token` 是**唯一**的访问控制。监听非本机地址（`--host 0.0.0.0`）时务必设置，
  否则同网络下任何人都能操作你的账号。
- **不要暴露到公网。** 没有 HTTPS，没有防爆破，暴露等于把账号交出去。
- 想换账号/退出：删掉 `cookies.txt` 重启，或重新跑 `bili_login.py`。

## 接口一览

都挂在 `/api/` 下。带 `--token` 时所有请求都要附 `?t=口令`。

```
GET  /api/me                         登录状态、硬币数、是否具备 CSRF
GET  /api/search?type=&q=&page=      type: video | bili_user | article
GET  /api/video?bvid=                详情 + 三连状态 + 关注状态
GET  /api/article?id=                专栏正文 + 统计
GET  /api/comments?oid=&type=&pn=    type: 1 视频 / 12 专栏
GET  /api/relation?fid=              UP主关注状态
GET  /api/user?mid=&page=            UP主资料 + 投稿列表
GET  /api/folders                    我的收藏夹
GET  /api/formats?bvid=              可用清晰度 + 估算大小
GET  /api/download?bvid=&q=          ffmpeg 合并后推流（预览和下载共用）
GET  /api/history?start=&end=&pages= 观看历史
GET  /api/history/export?...         导出 JSON
GET  /api/diagnose?bvid=             写操作自检，跑一对可逆操作并返回原始响应
GET  /biliweb.tar.gz                 自打包源码
POST /api/do                         {act: like|coin|fav|follow, ...}
```

`start` / `end` 接受 `YYYY-MM-DD`、`YYYY-MM-DD HH:MM` 或 epoch 秒。

## 实现说明

- **后端**：`http.server.ThreadingHTTPServer`，单文件，零第三方依赖。
- **前端**：单文件 `index.html`，原生 JS + 内联 CSS，无框架无构建步骤，
  移动端优先，适配了 iPhone 安全区，深浅色跟随 `prefers-color-scheme`。
  配色与排版参考 Apple 的 Web 应用规范（系统字体栈、分组列表、底部弹层、44px 触控目标）。
- **WBI 签名**：B站 搜索等接口要求签名，`mixin_key` 由 `img_key + sub_key` 按固定表重排后取
  MD5，密钥缓存 10 分钟。见 `Bili._sign`。
- **合并推流**：ffmpeg 把 DASH 的视频流与音频流 `-c copy` 合成 fragmented MP4，
  经 chunked 编码边拉边推，服务端不落盘。
- **登录**：B站 的链接/扫码登录是纯 HTTP 三步（生成 → 确认 → 轮询），
  `bili_login.py` 只用标准库实现，并会一并写入 `buvid3`/`buvid4` 设备指纹。

## 已知限制

- 在线预览的进度条不能拖动（合并流没有文件长度）。
- 清晰度上限取决于账号：匿名较低，登录后一般 1080P，大会员才有 1080P+/4K。
- 观看历史只能从最新往回翻，翻页上限决定了能回溯多久。
- 写操作偶尔会返回 `-403 账号异常,操作失败`，这是 B站 风控，等一段时间或换网络即可。
